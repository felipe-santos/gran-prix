Configuring the Retry Policy

The Tallowfield client can repeat failed requests automatically. This guide explains which failures are retried, how the delay between attempts grows, and how to turn the behaviour off.

Default behaviour

By default the client retries up to three times when it receives a network error or a response with status 502, 503 or 504. Requests that use unsafe methods are only retried when they carry an idempotency key.

Retry options

OptionTypeDefaultDescription
maxAttemptsnumber3Total attempts including the first request.
baseDelayMsnumber200Delay before the first retry.
factornumber2Multiplier applied after every attempt.
jitterbooleantrueRandomise each delay by up to half its length.

Example

The following snippet raises the attempt limit and uses a gentler growth factor.

const client = new Client({
  retry: { maxAttempts: 5, baseDelayMs: 150, factor: 1.5 },
});
const result = await client.get("/reports/weekly");

To disable retries entirely, pass retry: false when constructing the client.

Notes

  • Delays are capped at thirty seconds regardless of the growth factor.
  • A Retry-After header always takes precedence over the computed delay.
  • Retried requests keep the same idempotency key.
